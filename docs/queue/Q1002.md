# A consumer installing this for one verification skill is not told so

`verify-claims` lives here because the bundle that ships first should hold it,
rather than every consumer vendoring a copy and guaranteeing drift. That
decision was taken knowing it pushes a cost onto a different reader: somebody
who wants one verification skill has to install a repo of prose passes to get
it.

**The README does not say this.** It describes ten skills and a front door that
routes between them, which reads as a set you adopt whole. Nothing tells a
reader they may install `verify-claims` alone, and `install-skills.sh` accepts
skill names as arguments precisely so they can:

```bash
scripts/install-skills.sh verify-claims
```

**Why it matters more than a missing sentence.** The bundle this was extracted
from has a sibling set still unextracted that cites `verify-claims` six times.
When that set ships it declares a dependency on this repo, and its users arrive
here for one file. Discovering the shape at install time is the failure the
original decision explicitly accepted and said the README would absorb.

**The fix is a paragraph**, not a restructure: say which skills stand alone,
say that the router is optional, and show the single-skill install.

Filed at the extraction, 2026-09-13, carrying forward the cost the placement
decision recorded and did not pay.
