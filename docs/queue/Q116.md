# `readability` fires zero with both known levers deployed

The repo knows two things that make a skill fire: a description matching what
someone actually types, and a line in a loaded `CLAUDE.md` naming it at a
moment. `readability` now has both. It still does not fire.

Measured 2026-08-17 over 678 local transcripts, scored forward from the day both
levers landed:

| skill | total calls | since 2026-08-16 |
|---|---|---|
| `readability` | 1 (2026-08-06) | **0** |
| `deslop` (control) | 25 | 9 |
| a personal voice skill (control) | 94 | 18 |

The controls are what make the zero readable: the window is live, and skills of
the same kind fired 27 times in it. `7913aa8` rewrote the description from
transcript vocabulary on 2026-08-16, and the global `CLAUDE.md` names the skill
at a moment — "restructuring a doc, or explaining work to someone who won't
read the code". Both interventions are deployed and the count has not moved.

**The zero is testable rather than untested**, which is the distinction
`CLAUDE.md` insists on before acting on one. The applicable moment occurred: the
session taking this measurement wrote nine backlog rows and four PR bodies —
prose a reader who did not do the work has to act on, which is the skill's own
stated case — and never reached for it.

Two candidate causes, and they need separating before anything is rewritten
again.

**The naming line may be narrower than the actual use.** It names
doc-restructuring and explaining-to-a-non-reader. The stated use is blogs,
articles and Bluesky posts, none of which that line describes. If so the fix is
the line, not the description — and a global `CLAUDE.md` edit leaves this repo,
so the deliverable is a proposed line rather than a commit.

**The description's phrasings may still be invented.** `7913aa8` harvested them,
but `CLAUDE.md` records that a harvested description is scored on the turns it
was copied from and so reports fit rather than reach. Score the current
phrasings — "this is too verbose", "hard to read", "too dense" — against human
prompts that postdate the rewrite, per the forward-scoring rule.

Do not respond by broadening the description. `CLAUDE.md` measured that as the
failure mode rather than the fix, naming this skill as one of the two examples:
the two broadest descriptions in the repo were the two lowest in the table.

Caution for whoever picks this up: one day is a short forward window, and the
figures above will move. Re-run the count before acting, and treat a zero that
has grown a denominator as the finding rather than this row's numbers.
