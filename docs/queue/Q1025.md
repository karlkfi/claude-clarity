# A population asserted over but never sampled

Blocked by [Q1014](Q1014.md). This row parks a clause for a body held
shrink-only, so it cannot land alone. Q1003 settled the route as relocation,
and this row's clause lands **in Q1014's own branch** rather than after it:
room is made and spent inside one branch, because the grandfather baseline is
re-read per branch, so a shrink that merges makes main's smaller size the new
limit and banks nothing. Measured in [`decisions.md`](../decisions.md).

**Where it would land.** As a fourth cause under §*Where an unfalsifiable check
comes from* —
`skills/verify-claims/SKILL.md:42:## Where an unfalsifiable check comes from` —
whose closing line
`skills/verify-claims/SKILL.md:64:Only the third feels like a lapse while you are committing it.`
has to be re-cut for four either way. Budget about 800 bytes with that
re-cut, which is what it displaces from Q1014's 20.6 kB.

**The cause.** A claim quantified over a population that was never sampled,
made while the instrument that would sample it was already built and running.
The tell is that checking was nearly free and did not happen. It is closest to
`skills/verify-claims/SKILL.md:54:- **An untested input class.** The claim was checked across the inputs someone thought of, and one`
and differs in the way that decides how you search for it: an untested input
class is one the author believed was covered, so the search is *what did I
miss*. Here nothing was believed covered — a population was asserted over
without being looked at, so the search is *what is the cheapest check I did not
run*.

**The exhibit, which is the part worth publishing.** In a measurement session,
a predicate selecting sessions that edited source listed `.ts`, `.tsx` and
`.rs` — written from recall, matching **zero** sessions in the corpus — and
omitted `Makefile`, which matched 92. Deriving the list from the corpus took
one pass over a script the session already had. Correcting it moved the
denominator 734 → 741, because 124 of the 131 sessions those file types add
were already in the set via a `.py` or `.sh` in the same session. **A wrong
claim can survive correction with its number nearly intact**, which is why a
small agreeing spot-check is worse than none: it talks you out of the full
check. The rates that shape produced are private to a local transcript corpus
and are not needed to make the point; the shape is.

The same session hit the defect three times, each caught by one question from
the reader and never by the author's own review, and each correction taking
minutes on a corpus already in hand. The other two are provenance for the PR
body, not for the skill.

**Groom the neighbours before writing it.** Two rules already cover pieces:
`skills/verify-claims/SKILL.md:704:**A rule fires on a subject, so confirm the subject existed when the check ran.** A green check`
covers a predicate whose subject count is zero, and
`skills/verify-claims/SKILL.md:827:one level down and cost a single query: do those quoted phrasings occur in the corpus at all?`

of those two before spending the bytes.
