# Name the input that would fail the check, then look for one

Blocked by [Q1014](Q1014.md). The clause was written and reverted for want of
space, so it cannot land alone. Q1003 settled the route as relocation, and this
row's clause lands **in Q1014's own branch** rather than after it: room is made
and spent inside one branch, because the grandfather baseline is re-read per
branch, so a shrink that merges makes main's smaller size the new limit and
banks nothing. Measured in [`decisions.md`](../decisions.md).

**The clause, in the operational form that is the reason to file it.** Name the
input that would make this check fail, then look for one in the population.
Cannot name it: the check is not scoped yet. Can name it and the population
holds none: build one, or the run is a tautology. Two steps, performable on a
draft check in seconds. Most rules in this skill describe a defect and leave the
reader to spot it; this one is a procedure, which is the argument for its bytes
even where a neighbour describes the same defect.

**The measurement.** 2026-09-17 on `karlkfi/claude-spill-guard`, PR #170, the
`script-modes` gate. `scripts/check-script-modes.py` reads every tracked path's
index mode and first two bytes. The slow implementation is one `git cat-file`
per file; the shipped one is a single `git cat-file --batch`, blob SHAs in on
stdin and `<sha> blob <size>\n<body>\n` records out, parsed by walking a byte
offset forward record by record. That parser fails by **shifting offsets**, not
by erroring: size arithmetic wrong by one byte at record *k* means every record
after *k* reads the wrong body, so the answer is still well-formed, still one
row per file, still plausible, with modes attributed to the wrong paths.

Both implementations were run over the tree and all 260 rows compared. They
agreed, and that went out as verified.

A reviewer session ran the same comparison first, then asked the question above.
What distinguishes a correct `--batch` walk from a misaligned one is a record
whose length framing differs: an **empty blob** (size 0, so the body is zero
bytes between two newlines), or **two files sharing one blob SHA** — git emits
one record per *input line*, not per unique SHA, so a reader that de-duplicates
its input consumes more lines than it emits records and shifts everything after.
The tree contained neither. Naming them took one question, checking the tree one
command, building them three lines. That run is what established anything.

So the comparison was well-constructed, correctly executed and correctly read,
and its result was fixed before it ran.

**The correction that has to survive into the clause.** The first draft of this
lesson read "the trap is comparing against a reference walk and stopping". That
is wrong: the reviewer had run the same weak comparison, and the difference was
one more question on the same instrument, not a better instinct about which
instrument to reach for. A differential against a slow obvious implementation
stays the right move, so whatever lands must not read as a warning against one —
it is the follow-up question that finishes one.

**Where it lands.** §2's *Some instruments could not have gone positive at all*
is the neighbour, and the clause reads as a continuation of it: that rule's
closing procedure ends at "the fix is a different instrument rather than a closer
look", and here the instrument is right and the repair is a constructed input.
Four passages were read on 2026-09-24 and none states it — *A negative needs a
positive control*, *A control drawn from inside the enumeration it is testing
cannot fail*, *Uniformity across inputs you varied is a finding about the
instrument*, and §3's *size the fixture to the threshold*, which is this clause's
one-line instance for a threshold. *Uniformity* is the closest miss and does not
reach it: nothing was varied, and two implementations agreeing is what success
looks like. Whether this is its own rule or a clause folded onto *Some
instruments could not have gone positive at all* is open.

**Why it is parked rather than shipped.** The clause plus a re-cut of its
section's opening runs about 1,000 bytes. A branch paying that in place was
built and reverted on 2026-09-24: it passed `validate-skills` at 110,833 against
the 110,838 baseline, and the payment came from deleting the third exhibit of
*Some instruments could not have gone positive at all* (the probe fired where
the code path had already emptied its subject) and dropping three claims from the
two that remain. That is the exchange rate [Q1014](Q1014.md) measured and
forbids: compression over high-uptake prose returns tens of bytes per pass, so a
thousand of them is content leaving the file, not prose tightening.

and [Q1012](Q1012.md), plus the *population asserted over but never sampled*
