# Gate the two residency lines that say which reading you are holding

`scripts/rule-residency.py` prints a `# authoring repos` line on every run and
writes `verdict` and `repos` keys into `--json`, and nothing checks any of them.
A future edit can drop one and `make check` stays green. The row was filed
asking whether a suite built to avoid a corpus should take one to cover them.

**Measured 2026-09-19 at `6b88023`: it does not need one, and the check costs
54 ms.** A synthetic transcript tree — two project directories, one `.jsonl`
each, four records apiece — exercises the shipped path end to end with
`PROJECTS` reassigned, so nothing reads `~/.claude/projects`. The probe was 66
lines including its fixture. Three mutants of the instrument, each confirmed
landed by reading the file back: deleting the repos line reddens the two
assertions about it, deleting `"repos": repo_names` reddens the `--json` repos
assertion, and deleting the `r["verdict"] = verdict(r, reach)` loop reddens the
verdict assertion. Each mutant reddens its own assertion and no other, and all
six assertions ran in all four trees.

**Assert the discrimination, not the wording.** The review declined a `--help`
string check as a gate that fails on rewording, and that objection kills the
obvious form of this one too — `startswith("# authoring repos:")` reddens when
someone renames the prefix. The property the row is actually about survives it:
run the same synthetic corpus twice under two different `--repo` values and
require the two readings to differ, each naming its own segregation and
recording its own `repos`. Measured the same day, the two runs return different
first lines, different `repos` arrays and different verdict tables from one
fixture. That is falsifiable by a dropped line, insensitive to how the line is
phrased, and it tests the thing a reader needs — that a run says which reading
it is.

**The line earned its keep within a day of shipping, which is the case for
gating it.** A reading taken 2026-09-19 at `6b88023` returned 26 low-uptake
rules and 26,639 bytes where `docs/verify-claims-residency.md` records 21 and
20.6 kB, and the swing went unexplained. Re-taken the same morning at the same
commit: the flagged invocation the doc publishes returns 85 reader sessions, 11
authoring ones, `RAN=53 SAID=14 FLAT=7 BLIND=14`, and 21 rules over 21,120
bytes — the doc's table, a day and seven reader sessions later. The bare run at
the same minute returns 92 reader sessions, 4 authoring, `RAN=47 SAID=15
FLAT=12 BLIND=14`, and 26 rules over 26,639 bytes. The 7-session gap is the
`claude-skills` authoring sessions the second `--repo` segregates, which is what
the doc predicts and warns about in the paragraph above its table. So the
instrument is stable and the reading was the bare one; the `# authoring repos`
line printed `claude-clarity` alone and was the only thing in the output that
said so. Nothing gates the one line that made the difference legible.

**A second defect in the same file, folded in here rather than filed
separately** — the repair is two lines of fixture in the file this row already
edits, and a separate row would contend with this one on it. The harness check
named *mid-paragraph emphasis is not counted as a rule* passes with the
paragraph-opening guard deleted: 8 ok, 0 FAIL. The fixture's emphasis sits
mid-line, where `re.match(r"^\*\*...")` rejects it on its own, so the guard the
check is named for is never exercised. A fixture wrapping a bold span to the
**start** of a line separates them — `rules: 2` intact, `rules: 3` with the
guard gone. The shipped guard is correct; only the control is vacuous, so this
is a regression risk rather than a wrong number in the published table.

**What the implementing session also owes.** The harness header says *nothing
here touches `~/.claude/projects`*, and a synthetic corpus reads as
contradicting it — amend that comment to distinguish a fabricated tree from
machine state, or the next session deletes the new arm for violating the file's
own stated scope. Add a `docs/decisions.md` entry recording that a corpus-free
suite may fabricate a corpus, since the alternative is re-litigating it. The
repo's existing bar for building a check — certain and mechanically repairable,
from the entry refusing three linters — is met: a key is present or it is not,
and the repair is restoring the line.

**What would reverse it:** the probe reassigns `rr.PROJECTS`, a module global,
so a refactor making the projects root an argument or a class attribute breaks
the seam and the arm has to follow it. That is the coupling to watch; it is one
name, and the harness already imports the module by path for its verdict arm.
