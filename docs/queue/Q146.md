# A guard that never ran reads as a guard with nothing to say

`verify-claims` catalogues readings that cannot show you the opposite. One shape
is missing, and it was measured here rather than imagined: an installed hook that
fails before it runs is indistinguishable, from inside a session, from an
installed hook with no objection.

Measured 2026-08-18 over 739 local transcripts. Every one of `pipe-guard`'s 5,427
records, across 82 sessions between 2026-08-16 and 2026-08-17, is a
`hook_non_blocking_error` at exit 126 — its runner was not executable, so the
guard never once ran in the whole period it was installed. Nothing surfaced that.
A hook failing this way is non-blocking by design: the tool call proceeds, no
warning reaches the transcript's foreground, and the session sees exactly what a
clean run looks like.

The reading it corrupts is the one a session is most likely to take: *the guard
did not object, so the command was fine*. Every commit made in those 82 sessions
carried that inference, and the guard in question was the one enforcing the rules
about exit status that the same sessions were relying on.

## What would settle it

A shape in `verify-claims` covering enforcement that silently stopped enforcing,
with the check that separates the two readings — a hook has to be shown to have
*succeeded* at least once before its silence counts as a pass. The transcript
carries `attachment.type`, so the check is cheap:

<!-- check-fenced-code: an exhibit sizing the proposal below, not tooling to run from the store; a maintained probe under scripts/ is what this row asks someone to decide on -->
```bash
python3 - <<'PY'
import json, glob, os, collections
c = collections.Counter()
for p in glob.glob(os.path.expanduser('~/.claude/projects/*/*.jsonl')):
    for line in open(p, errors='replace'):
        if 'hookName' not in line:
            continue
        try:
            att = (json.loads(line).get('attachment') or {})
        except ValueError:
            continue
        if att.get('hookName'):
            c[(att.get('command', '')[-40:], att.get('type'))] += 1
for k, v in c.most_common():
    print(v, k)
PY
```

Filed by the session that worked Q121, which needed the distinction to avoid
reading two quiet days as two compliant days.
