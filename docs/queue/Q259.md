# A list asserts a symmetry its sentence never stated

Blocked on Q1014, and the dependency is a **same-branch** one — see *What
blocks this* below, because the obvious reading of it is wrong and costs a
session. Q1014 exists only on the branch for #13 as this is written.

A sentence that names one mechanism and then lists members licenses a reader to
distribute that mechanism over every member. Nobody writes the false claim; the
**format** carries it, and a reader picking up an item is entitled to assume the
category the list put it in.

Measured on 2026-08-24. The source sentence was accurate:

> Every command handler in `queue.py` returns 0 or 1 through `sys.exit(main())`,
> argparse contributes 2, and an uncaught exception contributes 1.

One mechanism named, and its three members reach their exit by three:

| member | mechanism |
| --- | --- |
| handler | return value through `sys.exit(main())` |
| argparse | `sys.exit(2)` called from inside argparse |
| uncaught raise | CPython top-level handler; `sys.exit` never reached |

A second session compressed the list into a causal chain, and the row it filed
then stated a `because` that is false — right value, right consequence,
invented cause.

**The exhibit above committed this row's own defect before review caught it.**
It first carried a fourth line, `missing file | interpreter startup`, and read
"by four". That member is not in the quoted sentence at all — it belongs to a
different list, the channel enumeration where `rc=2` arises two ways. The table
put it in the category the sentence had defined, which is exactly the mechanism
this row is about, and the count went with it.

**The obvious guard is defeated by the same example.** *Check every member
reaches the exit that way* returns **yes** for argparse, which genuinely calls
`sys.exit`. What is false is `sys.exit(main())`, the composed mechanism rather
than one of its parts.

**The guard that survives:** check each member against the mechanism *as
written, at the granularity it is written* — not against a component of it that
happens to be true. Or move the mechanism out of the sentence, which is what the
source needed: naming `sys.exit(main())` in a sentence covering three sources
was true of one of them and load-bearing for none.

**This is not a style note.** The failure survives a member-by-member check
honestly performed, because the check ran at a narrower granularity than the
claim. It is `A sound instrument still answers only its own question` turned on
your own prose, which is where that rule is hardest to remember to apply.

## Re-derived 2026-09-19, including the trace

The exhibit holds in this tree. `` `scripts/queue.py:1681:sys.exit(main())` ``
is the composed mechanism at that line; a clean `lint` exits 0 and an unknown
subcommand exits 2. Driven with `sys.exit` spied and `main` wrapped, both paths
reproduce the 2026-08-24 reading character for character:

```
argparse error:  TRACE=[('sys.exit', 2)]                        rc=2
clean run:       TRACE=[('main returned', 0), ('sys.exit', 0)]  rc=0
```

`main returned` never appears on the argparse path, so `main()` did not return
and `sys.exit(main())` never executed. The component is satisfied on both runs;
the composition only on the second.

## What blocks this

The rule cannot be short. The row's point is that the obvious guard *passes* on
the example, so the example has to be in the body or the rule reduces to a style
note. The tightest honest draft measures **1,047 bytes**, and the body is
grandfathered shrink-only.

**The dependency is same-branch, and the obvious reading is wrong.**
`validate-skills.py` takes `found = git("merge-base", args.base, "HEAD")`,
reads each body *at that merge-base*, and computes
`` `scripts/validate-skills.py:336:limit = max(ceiling, baseline)` ``. So the
room an addition gets is the gap between the branch's body and **its own**
merge-base — and a merged relocation moves the merge-base down with it.

Driven against a synthetic post-relocation tree rather than reasoned from the
source, both arms ending at the identical 90,452 bytes:

| branch | verdict |
| --- | --- |
| cut *after* a relocation merges, adds 1,047 B | **fails**, 1,047 over |
| relocates **and** adds in one branch | **passes** |

So *wait for Q1014, then add the rule* does not work, and it is the plan a
session reading `blocked on Q1014` would form. The rule has to ship **in** the
branch that performs the relocation.

## Options costed and rejected, so they are not re-derived

- **Take a rule out of Q1014's set to pay for this one.** Nothing in the 21
  low-uptake spans is absorbed by this rule, so it would be deletion for bytes.
  Q146 folded `A skip is not a defense` into its own rule because that rule
  genuinely carried the claim; there is no such target here. The two nearest
  `FLAT` spans are worse than neutral: `A figure you derived is not a figure you
  read` is cited by Q292, Q301 and Q1014's own table.
- **Compress high-uptake prose for ~1,030 bytes.** Measured yield across four
  passes on the Q146 branch: 100, 22, 48 and 60 bytes. Reaching 1,030 means
  cutting exhibits, which is the review finding that held that PR.
- **Rule in the body, exhibit in `references/`.** Gets the rule to about 600
  bytes and still leaves ~584 short, so it does not settle it alone. Worth
  combining with the relocation branch if that branch is tight.

Three items in one batch hit this wall, and the measurement was the same each
time: every unit in this body that can be cut without losing a claim is one the

among several — it gates every future addition to this body, including the three
rows it was filed for and this one as a fourth.
