# Publishing is undecided, and there is no path if the answer is yes

This is a local clone with no remote. The plan it was extracted under is
explicit that creating a public repository is an outward-facing act needing its
own decision, and that decision has not been made.

**The question is not only whether.** Nothing here covers what publishing would
need: a version scheme, a release process, release notes, or a
`.claude-plugin/marketplace.json` if the distribution is a Claude Code plugin
rather than a git clone people run `install-skills.sh` against. The skills sit
under `skills/`, which is the plugin layout, so the plugin route is open and
costs a manifest — but nobody has decided it is the route.

**What the answer changes.** If the repo stays local, most of the rest of this
store is optional polish and [Q1004](Q1004.md) in particular is a private
housekeeping question rather than a correctness one. If it goes public, three
things become blocking rather than additive: the corpus scope line has to
survive outside review, the grandfathered body in [Q1003](Q1003.md) becomes a
first impression, and the single-skill install the README now documents becomes
an instruction strangers follow.

**Ask:** publish or not. The plugin-or-clone half is now answered:
[Q1008](Q1008.md) takes a plugin manifest beside `install.sh`, because a hook
cannot reach a machine any other way without hand-editing a settings file. That
was decided for the hook rather than for distribution, so it constrains this
question without settling it. It does not make this row urgent: a local
directory works as a marketplace with no remote (measured in Q1008), so the
hook ships and runs here whatever this row decides, and what waits on the
answer is other people being able to install it.
