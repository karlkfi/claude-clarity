# Three rules land on a description with one character left

`verify-claims`'s frontmatter `description` measures **1023 characters against
the 1024 cap**, read from the enforcer on `05af7fb` by forcing `DESC_MAX = 0`
and taking the count out of `problems_with`'s own message. One character of
headroom, so `scripts/validate-skills.py` warns on it under Q201's band.

Three rules landed on this skill in one batch — Q218, Q148 and Q193, all
2026-08-22 — and not one of them could add a matcher clause for its own subject.
Two of the three subjects are unreachable through the description as it stands:
a population counted off a view already filtered by outcome, and a census that
returns almost its whole population. The third, a probe narrower than its claim,
is already covered by the existing *a sound instrument whose question is
narrower than the claim*.

`CLAUDE.md` is explicit that a description is a matcher rather than an
advertisement — it decides whether a skill fires *given* that its subject has
come up. So a rule nothing in the description reaches is available only to a
session that loaded the skill for some other reason, and a skill this broad is
loaded for some other reason most of the time. The cost is not that the rules
are unreachable; it is that the batch could not even weigh the trade, because
there was no room to write the clause and no decision to make.

## Why this is not the two rows beside it

**Q229** is the tooling half: `validate-skills.py` cannot report the count it
enforces, so a session that needs to know its headroom reimplements the fold and
gets it wrong on 12 of 21 skills. That row makes the number askable. This row is
about what to do once you have asked it and the answer is 1023.

**Q175**, in the collection this repo was extracted from, is the same class one
skill over — an orchestration skill's description does not cover its handback
section, at 1007 of 1024. Fixing it rewrites that skill's description and
closes nothing here: different file, different
enumeration, different trim decision. Two rows, one class, and neither fix
reaches the other.

## What a fix has to be argued against

`CLAUDE.md`'s *What makes a description fire*, in full. Three cautions bind:

- **A broader description is the failure mode, not the fix.** The two broadest
  descriptions in the repo were the two lowest in the invocation table.
- **The trim target is named**: budget for trigger phrasings first, cut the
  "Covers …" enumeration when it runs long. That enumeration currently lists six
  subjects against a body that now carries far more than six rules, so it is
  already a sample rather than a census — which is the argument for cutting it
  further rather than extending it.
- **Score forward, not over the turns the wording was harvested from.** A
  figure justifying the edit has to come from calls arriving *after* the
  wording ships, not from the turns it was harvested from.

Also worth settling rather than assuming: whether these rules need a trigger
phrase at all. `verify-claims` is named by the global `CLAUDE.md`, and
`CLAUDE.md` here measures that naming, not description breadth, as what makes a
skill fire — in which case the fix is nothing, and the row closes on that
finding.
