# A checker was refused as a gate and never scored as an instrument

**Demand:** a pass scoring whether skills should have fired asks for a figure
from one of the two skills left open below. For `code-restraint` that means a
corpus of authored diffs. For `rendered-page-review` it means page or README
source, which is what the 2026-09-24 pass scored. No such request has been
made since that pass.

[`decisions.md`](../decisions.md) refuses a linter for `semantic-remediation`,
`claim-provenance` and `tech-docs-layers` on one pair of criteria. A gate's
finding has to be **certain** and **mechanically repairable**, or it is a
warning a human must adjudicate, and that warning goes unread. An instrument
reports an aggregate over a corpus and has no actor to interrupt, so the
mechanical-repair criterion drops out. What replaces it is that the finding has
to correlate with the occasion the skill exists for, well enough that a rate
computed from it decides something.

## Whether the repo ships an instrument-only checker: moot until revival

**This question is still open, and it has no answer to act on yet.** No
candidate below passes, so nothing would be built either way. When the trigger
fires, the question goes to Karl, and it is a question about where the script
lives:

- **Repo tooling.** Precedent puts an instrument here. `scripts/rule-residency.py`
  (`134bd1a`, 2026-09-18) is one, and
  [verify-claims-residency.md](../verify-claims-residency.md) calls it "that
  instrument". It sits in the top-level `scripts/` and is never installed:
  `install-skills.sh` links only the directories under `skills/`
  (`` `scripts/install-skills.sh:125:for src in "$SRC_DIR"/*/; do` ``). It
  reaches the maintainer and nobody else.
- **A skill's own `scripts/`.** This is the shape the row asked about. It is
  the only one that reaches a pass run from another repo, and the one consumer
  on record ran from a private repo. That consumer reached `deslop-lint.py` and
  `readability-lint.py` because those ship inside their skills. The decisions
  entry records the reach in its *A bundled script is also not a second way
  into the bundle* paragraph. The cost of this shape lands on every installer.

No decisions entry says which of the two an instrument belongs in, so the
precedent covers the first shape and does not settle the choice between them.
What the precedent does settle is the harness. `scripts/test-rule-residency.sh`
is a behavioural correctness test that drives `--self-test` both ways, and there
is no catalog-sync test, because an instrument enforces no prose for a sync test
to compare against.

## Per skill, against the instrument criterion

- **`brevity`: fails.** Its body says "The floor is a property of the reader,
  not of the text". A script sees length and density, which are one side of the
  relation the skill exists for. That is the same one-term subtraction that sank
  `claim-provenance`, and it is as fatal to a rate as to a warning.
- **`substantiate`: fails.** It is a router whose body says "It does not
  author". Its occasion is the state of a draft (finished, about to
  be reviewed), which is not a property of the text. Anything it could count
  belongs to one of its passes, and two of those passes already ship linters.
- **`verify-claims`: fails.** Its finding is whether the evidence behind a claim
  could have shown the opposite, and the evidence is not in the text. What a
  script can read is the occasion list under *Fire this when*: verdict words and
  numbers. Counting those is the description restated, which is the predicate
  the decisions entry dismisses as measuring the paraphrase. It also marks about
  half of all prose. The test was whether a paragraph contains one of the body's
  seven verdict words (`passed`, `failed`, `clean`, `done`, `fixed`, `empty`,
  `none`) or a digit. It was counted over this repo's Markdown on 2026-11-01,
  taking paragraphs of 20 words or more, with fenced code, tables and headings
  removed. Over `git ls-files '*.md'` minus the 2 files under `testdata/` (40
  files), 445 of 928 paragraphs match, 48.0%. A first run that globbed the
  filesystem instead gave 47.5%, and the review's re-run over all 42 tracked
  files gave 47.0%. The argument holds at any of the three. This is a proxy
  over this repo's prose, not over the pass's corpus.
- **`rendered-page-review`: open, and it is a measurement.** Its section
  *What to mechanize, and what not to* names three certain checks. One, no
  horizontal overflow at 320px, needs a render. The other two, the body says,
  "are countable in the source": callout run length, and one component carrying
  identical content on two pages. Its description covers READMEs, which is the
  pass's own corpus. So a source-only count is possible, and what is unknown is
  whether a rate over it would decide anything. One sign the rate might be thin
  is the body's own calibration. In the repo the skill came from, the longest
  surviving callout run anywhere was 2. That figure comes from the skill's
  home repo and was not measured here.
- **`code-restraint`: open, and it is a measurement, not a build.** The metric
  is already in the body as copyable `awk` (Step 1's comment density, and Step
  4's added-against-host ratio with its roughly-2x bound), so a script would
  add nothing computable. What is unknown is whether the ratio correlates with
  the occasion. The body itself breaks the per-diff reading: on a
  machine-written baseline, "matching it locks the slop in". The row asked
  whether an aggregate over many diffs survives that, and nothing here can test
  it, because the test needs a corpus of diffs labelled for whether the skill
  should have fired. The pass on record scored README prose, which
  `code-restraint` excludes.

## Cost, measured 2026-11-01

`wc -l` per linter: `deslop` 354 lines (208 script, 146 across its two tests),
`readability` 370 (177 script, 193 tests). The precedent instrument is 543
(`rule-residency.py` 428, its test 115). An instrument therefore costs a script
plus one correctness test, and a gate-linter's catalog-sync test is the part an
instrument does not carry.

## What this does not reopen

The three gate refusals stand. `claim-provenance`'s obstacle carries over
unchanged: a script reads the register and never the provenance.

**Who it is for, and what it costs never built:** the session running a
should-have-fired pass. Without a figure for `code-restraint` or
`rendered-page-review`, that pass scores those skills against a paraphrase of
their descriptions, which is where it already is for eight skills. **Rate:** one such pass on record (2026-09-24), and its
instruments live in a private repo. The cost is steady, neither accruing nor
perishable. **Rank on revive:** `b1f` holds. Revival is a measurement sized S
per skill, then Karl's placement question, and a build only if the measurement
comes back positive.
