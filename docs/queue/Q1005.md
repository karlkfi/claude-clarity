# A runnable fence names a gate script this repo does not have

`verify-claims` carries a worked probe for falsifying a gate's waiver arm, and
its fence invokes `scripts/check-fenced-code.py` — a gate that stayed behind in
the collection this repo was extracted from. Nothing here resolves that path.

**Left deliberately, and worth a second opinion.** The rule the extraction used
is that an exhibit may name something the reader cannot open, because
provenance that dangles costs them only a lookup they were never going to make;
an *instruction* may not, because a dangling path there costs them the command.
This was read as an exhibit: the prose introducing it says "Against a
fenced-code gate of my own", which hands the reader their own gate rather than
this one.

**The reading that says it is a defect** is the sentence three lines later —
"the probe is how you check yours is one" — which is an instruction to run it.
A reader following that has to notice the script name is a stand-in, and the
fence gives no sign that it is.

**Three repairs, and picking one is the work.** Rename the invocation to an
obvious placeholder, which breaks the block's internal consistency with the
`<!-- check-fenced-code: ... -->` waiver comment beside it. Rewrite the whole
block against a generic gate, which costs the recorded exit statuses their
subject. Or leave it and add one sentence saying the script is the author's and
the reader substitutes their own — cheapest, and the only one that does not
touch a recorded run.

**The body is grandfathered shrink-only**, so a repair that adds a sentence
names what it displaces. The room comes from relocation and from nothing else
([`decisions.md`](../decisions.md)); [Q1014](Q1014.md) is the move.

Filed at the extraction, 2026-09-13, by the session that made the call.
