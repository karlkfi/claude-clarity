# `rendered-page-review` is named in no `CLAUDE.md` and has never fired

Measured 2026-08-17 over 678 local transcripts: **zero invocations, ever**, in a
window where `deslop` fired 25 times and a personal voice skill 94. It is the only
skill in the repo with a lifetime count of zero that is also installed.

One lever is deployed and one has never been tried. `5936cb8` broadened the
description on 2026-08-16 to trigger on "pages a site actually publishes", which
is the description lever, and it has produced nothing since. The naming lever is
untouched: no `CLAUDE.md` anywhere names this skill as something to invoke. The
global one mentions it exactly once, at line 78, as the *subject* of the
measurement — "`readability` was invoked once and `rendered-page-review` never"
— which is a citation, not a naming, and cannot fire anything.

That makes this the cleanest available test of the repo's central claim about
triggering, because the two levers have not been confounded here the way they
have on [Q116](Q116.md). If naming moves this count off zero, naming is
confirmed as the decisive lever on a skill whose description lever demonstrably
did not move it.

The stated want is automatic triggering when working on web pages and docs.
Three shapes carry that, and they differ in reach and in who approves them:

- **A line in the global `CLAUDE.md`.** Reaches every repo. Leaves this repo, so
  it is a proposed line rather than a commit.
- **A repo-local line in each repo that publishes a site.** Narrower and lands
  as an ordinary PR per repo, but it has to be added repo by repo and a new
  site-publishing repo starts without it.
- **A hook on edits under a docs path in a repo carrying `mkdocs.yml`,
  Docusaurus or Hugo.** Deterministic rather than model-invoked, and the only
  shape that fires without anything having to remember. Costs a hook to
  maintain, and it fires on every such edit whether or not a review is wanted.

**Whichever shape wins, the line must name a moment rather than a condition.**
`CLAUDE.md`'s control for this is a skill framed "at session start and
whenever the task type shifts", which produced zero invocations. "Whenever
working on web pages" is that same ambient shape, so it needs rewriting into
something with an occasion in it — reviewing a page before it ships, or a docs
change in a repo that serves one.

Filed at the maintainer's request after a forward score found both this skill
and `readability` at zero since their 2026-08-16 rewrites.

**Measure:** re-run the forward score. Like [Q116](Q116.md) this is a reading that can only fall or rise with the corpus, and the rewrite it argues for should be scored against the window after it ships rather than the one before.
