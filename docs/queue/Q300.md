# A benchmark control taken in a second process licenses nothing

`verify-claims` §1 has the negative form of this rule twice, and neither reaches
a benchmark. `` `skills/verify-claims/SKILL.md:341:— and treat agreement between two runs sharing a setup as one reading, not two.` ``
says a shared setup makes agreement worthless, and
`` `skills/verify-claims/SKILL.md:546:**take the baseline before the scarce run, with the thing not yet done**, which turns the` ``
says to take a baseline before the run that would contaminate it. Both are about
a baseline that is *too close* to its arm.

**The benchmark failure is the opposite one, and no rule states it.** A control
arm is what licenses comparing two runs at all, and it can only do that when it
is measured in the same process as the arm it licenses. Split across two
sittings it moves with the machine, and the primary rows then differ by an
amount nobody can attribute. *Measure it* and *measure it against something that
could invalidate the comparison* read as one instruction.

## Measured 2026-09-08 on `karlkfi/claude-spill-guard`

The Q164 lane's first `BenchmarkRuleset` reading was two separate runs and read
as a **2× regression**. The control — every `Anchor` cleared — had gone
7.12–7.40 → 3.31–3.42 MB/s across the two, and an untouched rule's fixed cost
1.85×. The machine was loaded, so nothing in that run was attributable.

**The control caught it, in the same turn, and this row is not a report of a bad
number shipping.** At 02:19:28Z the lane wrote *the control arm moved 7.4 → 3.1
MB/s and an untouched rule's fixed cost doubled — the machine is loaded, so this
run is not attributable. Checking, then measuring both rulesets in one process*,
and re-measured in one process. Its handback credits the brief: *Your control
arm earned its keep.*

That is what makes the gap a contract gap rather than an incident. The control
was in **one orchestrator's spawn prompt**, written by a session that had
learned it. Neither the worker-contract skill outside this repo nor `verify-claims`
carries it, so the next lane that benchmarks gets it only if the next
orchestrator happens to know.

The orchestrator's own later re-measurement states the positive form the run
arrived at, and it reached the shipped v0.4.0 release notes: the control at
7.24–7.39 and 7.37–7.40 MB/s across two runs hours apart, *which is what
licenses comparing their first rows at all*.

## Direction

The rule to write is that a control licenses a comparison, and only from inside
the same process as the arm — so two runs are comparable only where their
controls agree, and the agreement is stated rather than assumed. Placement is
the work: `verify-claims` §1 already holds four rules about baselines and
agreement, and this is a fifth statement near them rather than an obvious
insertion. The worker-contract skill outside this repo is the other candidate,
being where a lane reads its gate rules, but its control rules are about a
checker's mutated input and not about measurement.

`verify-claims` is far past its ceiling and held shrink-only, which
[Q1003](Q1003.md) owns and measures; do not restate its figures here. So an
addition there names its displacement — the budget raise that used to be the
alternative is gone. The other candidate body is not in this repo, so its size
cannot be read from here and that half of the placement call belongs to whoever
holds it.
