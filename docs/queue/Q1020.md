# Eleven trigger phrasings are typed by nobody, and a cut buys nothing

Blocked on a measurement this repo cannot take — see *What would unblock it*.

`CLAUDE.md` says to harvest trigger phrasings from real transcripts and never
invent them. A pass handed here on 2026-09-24, over 1,574 measured sessions
from one workstation, says eleven phrasings quoted verbatim from these skills'
own descriptions were invented: each occurs **zero** times across populations
of 411 to 1,489 sessions.

| phrasing | carried by |
|---|---|
| "sounds like ai", "reads like ai", "reads as ai" | `deslop`, `code-restraint` |
| "too many comments", "too defensive" | `code-restraint` |
| "too dense", "verbose", "shorten", "skimmable" | `readability`, `brevity` |
| "fresh eyes" | `semantic-remediation` |

What people do type is blunter. `slop` appears in 45 sessions with 21 fires —
but that is `deslop`'s own name-root, so typing it is naming the skill rather
than describing a complaint. `confusing` is 6 sessions and 1 fire, "too long"
is 2 and 1.

Two more terms are measured worse than dead. **`prose` is anti-predictive for
`deslop`**: 216 sessions contain it and 3.2% of those fired, against a 4.1%
base rate. `write` (374 sessions, 5.3%), `doc` (575, 4.9%) and `readme` (221,
5.4%) all sit within noise of base, so the high-volume vocabulary in that
description discriminates nothing.

## Why this is blocked rather than ready

**Nothing measured says a cut helps.** `decisions.md` settles that recovering
characters buys no invocations, and nine of the ten descriptions already sit at
about a tenth of the cap while calls span 28-fold. A phrase that matches
nothing costs nothing except where it wrongly matches, and only `prose` has a
reading pointing that way.

**The zero is a zero in one person's corpus.** These skills ship to people who
did not write them, and "nobody on this machine typed it" is not "nobody types
it". The instrument cannot distinguish an invented phrasing from a real one
this corpus's author has no occasion to use.

**The dominant finding is that the description is not the lever.** Naming
dominates 11 of 13 rows in that pass, from 1.6:1 for `deslop` to 15.4:1 for
`tech-docs-layers`, and 49% to 86% of these skills' calls follow a turn naming
the skill outright or a brief that does. Editing descriptions is work on the
term that was measured not to matter.

## What would unblock it

**Measure:** a forward-scored reading — calls arriving after a wording ships, never over the
turns it was harvested from — in which a description carrying one of these
phrasings loses nothing when it goes. That is the same measurement
`decisions.md` names as missing for the cap question, which is a reason to
build it once for both.

Failing that, a second corpus from someone who did not write these skills,
which turns "zero here" into a claim about the phrasing rather than about the
author.

## Direction, when it unblocks

One skill per commit. Skills here deliberately share phrasing about each other,
so a script substituting text across several `SKILL.md` files at once hits
neighbours silently.

`prose` is the one candidate that does not wait on either unblock, because
anti-predictive is a different finding from absent. Even there the repair is
not obvious: `deslop` is about prose, and a description that stops saying so is
less accurate in exchange for an effect nobody has measured.

Filed 2026-09-24 from the measurement pass. The counts are handed over, not
re-derived here. The instruments live in a private repo and this tree cannot
re-run them.
