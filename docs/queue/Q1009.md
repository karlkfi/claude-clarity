# The documented way to ask a skill's description length does not work

`scripts/validate-skills.py --report deslop` prints
`validate-skills: deslop: no SKILL.md found` and exits 1, for every skill in the
repo. Measured 2026-09-14 from the repository root.

The global `CLAUDE.md` names that exact command as the way to get the number
rather than refolding a block scalar by hand, and the script's own usage
docstring carries it as
`` `scripts/validate-skills.py:74:scripts/validate-skills.py --report deslop  # one, by name or by path` ``.
So the failing invocation is the documented one, in two places.

**The cause is that `resolve` never consults the skills root.** It tries
`Path(name)` and `Path(name)/"SKILL.md"`, both relative to the working
directory, so a bare name resolves only when the caller is standing inside
`skills/`. The same command run from `skills/` works, and so does a path from
anywhere:

```bash
python3 scripts/validate-skills.py --report skills/deslop/SKILL.md
```

**What makes it worth fixing rather than redocumenting**: the gate itself
already knows where skills live — it walks `skills/` with a fallback to the repo
root, which is the discovery `resolve` should be reusing. Three lines, and the
repair is the same one the docstring already promises.

Found while grooming [Q1004](Q1004.md), reaching for the description length of a
skill whose row was being re-measured.
