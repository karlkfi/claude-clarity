# Correcting a claim where you found it is what hides its other copies

Blocked by [Q1003](Q1003.md). This row parks a clause for a body held
shrink-only, so it cannot land until that pass decides where the room comes
from. Q1003 is deleted and its settlement re-filed as Q1014 by an open pull
request, so this blocker re-points when that lands, the same way Q274, Q1010
and Q1012 do.

**The measurement, handed over rather than re-derived here.** One
`session-worker` session in `claude-spill-guard` carried two backlog rows to
`karlkfi/claude-spill-guard#172` and `#173` on 2026-09-19. Both landed green —
61 checks success and one tag-gated skip on each head — and both were correct in
code. Seven claims across them were wrong, and all seven were prose: commit
messages, code comments, PR bodies. None was in code, none was reachable by any
gate, and every one was caught by re-reading a document against the tree. Five
are ordinary unmeasured assertions of scope or count, which `claim-provenance`
already owns. Two have a mechanism nothing here names; this row carries one and
[Q1018](Q1018.md) the residue of the other.

**The case.** A code comment on a rebuilt test fixture said it was the one case
in its file that went round the loader deliberately. It was false when written:
`internal/scan/scan_test.go` already held two tests building `rules.Rule`
literals directly, with a comment of their own saying why. The author found the
error, fixed the comment, and wrote a commit message describing the correction —
and that commit message is what stopped anyone looking again. The claim stood
verbatim in #172's PR body and survived the fix, found only by a later re-read
that had gone in for something else.

**The tell is that the repair produces the evidence that the repair was
complete**, and that evidence is the most authoritative-looking artifact in the
session: a diff showing the wrong sentence gone, and a commit message narrating
why. Ask what a reader would see if the claim also stood somewhere nobody had
opened, and the answer is *this exact diff*. A claim asserted once is usually
asserted twice, because the sentence that went into the comment and the sentence
that went into the PR body came out of the same paragraph of thinking. So the
search is for **the claim, not for the file just edited**, and it runs before the
correction rather than after it, while the original phrasing is still to hand.

**Where it would land, and what it hands off to.** §2 already covers the sweep
that was run and came back blind — *A sweep that comes back clean has told you
about its own representation* and *A clean sweep and a blind one both print
nothing*, with four structural reasons under them, measured on a review where
three sessions each enumerated every site asserting one claim so that claim
could be corrected. This row sits one step upstream of that family: no sweep was
run at all, because the fix looked complete. The clause is the family's missing
entry condition and should hand into it rather than restate it — which is also
what keeps it small, since everything about making the sweep non-blind is
already written a page above.

**Not `claim-provenance`.** That skill audits whether an author earned a claim,
over one draft at a time. Here the author had earned it at the site they fixed,
and the two copies sat in different artifacts — a Go comment and a PR body — so
no single-draft pass reads both. What is in doubt is whether the signal taken
after the repair could have shown the remaining copies, which is this skill's
question.

Filed 2026-09-21. The seven instances and the two PRs are the measuring
session's; the coverage reading against the current body is this session's.
