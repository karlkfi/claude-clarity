# A change that can fail in two directions needs a mutation per direction

Blocked by [Q1003](Q1003.md). The fold was written and reverted for want of
space, so this row cannot land until that pass decides where the room comes
from.

Two sessions fell into the same gap on 2026-09-18, on different files, within
the same hour of one parallel-dispatch run on `karlkfi/claude-pr-sentinel`. Both
cases below were measured in that run. They are not independent: case 1's
reviewing session is case 2's actor, so the second skip was made by the session
that had just diagnosed the first. What is observed is same run, same hour,
different files, different actors — two occurrences of the shape, not two
arrivals at it from nothing.

**The rule, in the actionable form reached in that run:** where a change can fail
in two directions — too strict and too permissive — each direction needs its own
mutation, and the skipped one is whichever the headline test does not point at. A
control is a control only once some mutation has reddened it.

**Case 1, the asymmetry.** A Stop hook's dampening signature was made
order-independent: a `Failed checks:` line split on `, ` and compared as a sorted
tuple rather than as a raw string. Its suite is a headline assertion (same
membership, different order, must dampen) plus two controls — a reordered set is
still not a changed set, and a check literally named `trivy (agc, 1) (fail)` must
not split into a match. The author's inversion reverted the function to the
exact-string compare: 5 failures including the headline, read as the change
verified. That mutation makes the function **stricter**; the controls exist to
catch it becoming **more permissive**. A reviewing session then replaced the
function body with a constant `()` — also 5 failures, but reddening both
controls, which the first mutation had not. Until that run nothing had
established the controls could fail at all, and the permissive direction is the
one that makes "dampen" quietly mean "always".

**Case 2, the same skip in a timing shim.** Inverting a test shim to reproduce
another session's timing claim, the reviewer replaced the shim's `exec` line and
left its `sleep` in place: baseline 5.428s passes, `exec` replaced with `sleep`
kept 5.432s still passes, both lines replaced 0.31s fails with a message naming
the cap. The middle row is the finding — a mutation that removed the handover for
real and still could not move the assertion, because the assertion was keyed on
the timing and only the `sleep` held that. The reviewer briefly read that green
as the original claim failing to reproduce.

**Where it lands, and why it is not landed yet.** §3's bullet *Delete one
mechanism, not the branch around it* is the closest neighbour and states the
inverse concern — a coarse mutation measures only that the path is reached —
where Case 1 has the coarse mutation being the informative one. The fold is that
bullet, stated as one rule with two failure directions. The four other passages
checked on 2026-09-18 and none states it: *A mutation aimed at a constant tests
the constant*, §2's *A control drawn from inside the enumeration it is testing
cannot fail*, *A negative control that an empty run satisfies is not a control*,
and the waiver-hatch paragraph's *arms in both directions*.

The fold was written and reverted the same session: at 1,164 bytes it failed
`validate-skills`, which holds this body shrink-only against its merge-base size
(110,854 bytes on 2026-09-18). No displacement was found that did not cost a
measured case, so the content is parked here rather than traded against one by
whichever session happened to notice. [Q1003](Q1003.md) is the pass that would
create the room, and it is further out than its own PR: that PR delivers a
residency instrument and a reading, touches no skill body, and leaves Q1003
`ready` with the relocation still undecided. This row waits on that decision,
not on that merge.

**Two siblings park the same conclusion with different tells**, and all three
compete for the same shrink-only space: [Q274](Q274.md) on a cross-check that is
an identity rather than a comparison, [Q1010](Q1010.md) on a control drawn from
the artifact under test. This row's tell is the asymmetry — which direction the
mutation goes. Whether the three fold into one clause is open and is argued in
Q1010; each row owns its own measurement and none restates another's.
