# rule-residency.py cannot read a skill's reference files

`scripts/rule-residency.py` takes one Markdown file and names the skill after
its parent directory:
`` `scripts/rule-residency.py:401:    skill = path.parent.name` ``. Since
`verify-claims` was split by moment on 2026-10-25, its body holds 4 bold-lead
rules and its eleven `references/` files hold the rest. Pointed at one of those
files, the probe looks for sessions invoking a skill called `references`, finds
none, and exits 2. So a residency reading of the rules that moved cannot be taken
at all, and the doc already says the tables are not comparable "until the
reference files are counted too".

**Measured 2026-11-01**, on the tree carrying the wrapped-lead fix that separates
a lead whose bold span closes on a later line: `load_rules()` finds 162 rules
across `skills/verify-claims/references/*.md` and 4 in `SKILL.md`.
`scripts/rule-residency.py skills/verify-claims/references/negatives-and-controls.md`
prints `no transcripts under /Users/karl/.claude/projects carry a Skill call for
'references' -- nothing to measure` and exits 2.

**What a fix has to decide, which is why this is not a one-line change.** A
reference file is loaded by a Read, not by the `Skill` call `transcripts()` keys
the `PRE`/`POST` split on, so the window boundary for a reference rule is the
first read of its file, and a session that never read the file is not a reader
of those rules at all. Naming the skill from the path (`--skill`, or walking up
to the directory holding `SKILL.md`) is the easy half; the control arm is the
part that needs a design, and the decisions entry on the split names reading
rates of the files as its own reversal condition.

Filed 2026-11-01 from the wrapped-lead fix, which found the 19 leads it
separates all sit in files this probe cannot measure.
